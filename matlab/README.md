# MATLAB / Simulink tools

The analyses were first developed in MATLAB and Simulink. This folder holds
rewritten versions of those scripts. They share one parameter set and read the
CSV records in [`../data`](../data), and the Simulink models are generated by
script. The Python package is the reference implementation. Each script prints
the matching Python numbers so the two can be compared.

```matlab
cd matlab
setup_adapt_ctrl_sys_id   % adds the folders below to the path
servo_identification      % ...then run any script
```

**Requirements:** MATLAB R2020b or newer. You need Simulink only for the model
builders. The Control System Toolbox is optional and only used by the
`pidtune` comparison in `pip_design`. No other toolboxes are needed:
least squares, RLS, lock-in analysis and fitting use base MATLAB (`\`,
`filter`, `fminsearch`, `ode45`).

`adapt-ctrl-sys-id twin serve`. The default address is `localhost:10815`.

## Changes from the original scripts

- **One source of truth:** the masses, lengths, identified constants and
  design choices are defined in `common/acsi_params.m`. The original scripts
  copied them by hand. The `.mat` recordings were converted to documented CSV
  files.
- **Time constant:** one script used `T = 0.31819 s`. The value identified on
  the servo is `T = 0.31919 s`, and its corner frequency `1/T = 3.1329 rad/s`
  is the middle frequency of the sine tests.
- **Twin client:**
  - The loop compared the scalar measurement with an uninitialised vector
    (`phiRef` instead of `phiRef_`).
  - The rotor command was not limited to 0–100 %.
  - `pidtune` ran in every 10 ms cycle. The design now runs once before the
    loop.
  - The deprecated `tcpip`/`fopen` calls were replaced by
    `tcpclient`/`readline`/`writeline`.
- **Step response:** the earlier identification attempt used the reference
  angle as the model input on a 2 ms grid. It now uses the rotor command in %
  on an anti-aliased 50 ms grid, and the coefficients are mapped back to
  physical parameters.
- **Free fall:** the release delay and the damping were chosen by hand. They
  are now estimated together with the inertia and the air drag.
- **Simulink:** the builders create the block diagrams with `add_block` and
  `add_line`. The MATLAB Function block script is set through the Stateflow
  API, and the parameters are stored in the model workspace. No binary
  `.slx` files are kept in the repository.

## Model Scope

The servo builder uses the linear PT1 plant, without the Python virtual
servo's encoder quantisation or nonlinear losses. The pendulum builder
includes PI-P, feedforward, rotor lag and nonlinear damping, but omits
conditioning anti-windup and the startup dead band. Use `pip_simulation`
or the Python package for the full controller comparison.

## Quality checks

CI runs [MISS_HIT](https://misshit.org) on this folder (`mh_style` and
`mh_lint`, configured in `miss_hit.cfg`), so syntax errors and style drift are
caught on every push. MATLAB is not available on the CI runners, so CI does not
execute the scripts. The MATLAB scripts and generated models have not been
runtime-tested here. The Python test suite validates the Python implementation,
not cross-language numerical equivalence.
